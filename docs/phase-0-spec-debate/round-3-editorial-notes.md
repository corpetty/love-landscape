# Round 3 — Editorial Notes (spec)

Abbreviations: RA = Research Advocate, NA = Narrative Advocate, AD = Adversary.

## Addressed — the structural fix

1. **NA#10 + AD#4 + NA#2/#3/#4 — claim-time re-keying replaced with a `claims` link table, resolved at read time.** Milestones become truly append-only (no UPDATE carve-out except the deletion pass, enforcement stated per NA#4); create milestones carry `client_result_id`; person(create) = claims-resolved. This single change eliminates: the re-key-vs-flush race (a late flush's `client_result_id` is already claimed → resolves correctly), the shared-device sweep (claims are result-scoped, so the checkbox UI's promise is now real at the milestone layer), and the "one human = two persons" post-claim split. The v3 machinery the round called "the most fragile in the spec" no longer exists.

## Addressed — gate-integrity bugs

2. **AD#1 + NA#1 — milestone idempotency:** create milestone written only when the upsert *inserts*; conflicting fields ignored (write-once `status` cannot be overwritten via a stale queue flush); partial unique index `(kind='create', client_result_id)` backstops replays; publish/waitlist/purchase milestones keyed to their own first-transition guards.
3. **AD#2 + NA#12 — flush-time corruption fixed:** milestones carry `happened_at` (client, bounded by server receipt, ≤30 days old); gate SQL windows on it — shakedown completions cannot leak past freeze, B reflects real timing, and the velocity check (on `occurred_at`) is documented as flush-aware.
4. **AD#3 — the H-inflation hole closed by construction:** the durable queue entry holds the *full* create payload (status, variant, completed_at); features flush that entry rather than minting degraded creates — no status-NULL create path exists. Loaded partner codes never mint results (phantom-A hole named and closed); waitlist joins are server-rejected without a prior create, making H's numerator ⊆ denominator structural.
5. **AD#5 — E made computable:** inline OTP flows (waitlist, save) perform an implicit claim of the single in-context result; the `signup` op (new, also fixing NA#5's unauthored milestone) creates the profile, writes the milestone, and links create→user. Acceptance for F0.1 includes a test query proving the linkage.
6. **AD#6 — the pathname leak fixed:** sharedView's CTA does `replaceState('/')` before the assessment; `__SHARE__` is one-shot and takes stated precedence over `?code=`; post-CTA refresh cannot re-fire `share_page_view` (regression test added). D's "bias cancels" claim is restored honestly.

## Rejected

1. **AD#8(b)'s implicit demand to encrypt the localStorage queue.** Rejected: the saved result's code already lives in localStorage in the shipped product; client-side encryption against an attacker with device access is theater (the key must live beside the data). The honest mitigations are the 30-day TTL, deletion clearing, and disclosure — all adopted.
2. **NA#10's suggestion to replace `rate_counters` with something off-the-shelf.** Rejected: an external rate-limit service adds a vendor and a network hop to every funnel write; fixed-window Postgres counters are ~30 lines and now fully specified. Revisit only if load proves otherwise.
3. **RA#4's strictest reading — measure F0.8 acceptance over completers.** Rejected as unmeasurable by definition (completers whose write failed are invisible to the server); adopted instead as declared deviation 4 with a stricter threshold, which is the honest version of the same intent.

## Convergence note

Three rounds reached the cap without a formal `NO MAJOR ISSUES`, but the trajectory converged: round 1 forced architecture reversals (share pages, OG rendering, auth method, metric sourcing), round 2 forced the data-plane and identity design, round 3 found implementation-order bugs in that design — every round-3 finding had a one-to-three-sentence fix, and the round-3 adversary's own verdict was that the machinery "genuinely closes the v1/v2 holes it targets." The remaining known risks are carried openly in the spec (§11 open questions, residual identity biases, fraud-through-rate-limits, F's bias direction) rather than resolved by assumption.
